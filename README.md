# NIST SP 800-82r4 (initial public draft) OT overlay in OSCAL

**Unofficial.** This is a machine-readable rendering of the SP 800-53 Rev. 5 OT overlay in
Appendix E of the *initial public draft* of NIST SP 800-82 Rev. 4, *Guide to Operational Technology
(OT) Security* (21 September 2026). It was generated by script from the draft PDF. It was not
produced, reviewed or endorsed by NIST. The draft can change before it is final, and so can this
rendering. For anything that matters, read the PDF.

Source PDF: https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-82r4.ipd.pdf
SHA-256 `66e00d5c8dbbfaf0342890e75d2492f72e1ef34da81df5c6a94cc339bd91f683`

## How the overlay is modelled

An overlay tailors the SP 800-53B baselines, so it is modelled as OSCAL **profiles**, not as a new
catalog. Each profile imports NIST's SP 800-53 Rev. 5 OSCAL catalog and includes the controls the
overlay places in that baseline: every control marked "Select" or "Add" in the E.7 specification
tables.

| Baseline | SP 800-53B | Select | Add | Remove | Overlay |
|---|---|---|---|---|---|
| LOW | 149 | 149 | 11 | 0 | 160 |
| MODERATE | 287 | 285 | 19 | 2 | 304 |
| HIGH | 370 | 367 | 20 | 3 | 387 |

Within each profile:

- **OT Discussions** are added to each included control as a part named `ot-discussion`.
- **Rationales for additions** are added as parts named `ot-rationale`.
- **Added controls** carry a prop `ot-overlay-action = added`.
- **Removed controls** are listed as `ot-overlay-removed` props in the profile metadata, with the
  draft's rationale, because a profile cannot alter a control it does not include.
- The source line number of each quoted passage is kept as a `source-line` prop.
- Props and parts use the namespace `urn:uuid:5c1f1a0e-82a4-4d0e-9b8a-0f8a2d0c8204`.

Not in the profiles, but present in `data/overlay-r4-ipd.json`:

- OT Discussions for controls with no baseline allocation: the PM family, and controls such as
  CM-3(7) and SC-32.
- Family tailoring notes.

## Checks

`scripts/build.py` refuses to write anything if any control ID is missing from, or withdrawn in,
NIST's SP 800-53 Rev. 5 OSCAL catalog. Every build also checks:

- Table 18 (summary) against the E.7 detailed tables, per baseline;
- Select/Add/Remove against the SP 800-53B baseline profiles;
- Rev. 3 against Rev. 4 ipd, row by row;
- Table 18 bold (the key says bold marks controls with an OT Discussion) against the extracted
  discussions;
- each rationale against an Add or Remove marker;
- printed control titles against SP 800-53 Rev. 5;
- subsection numbering.

Results are in `reports/consistency.md`. All of the table-level checks agree. The draft defects
found are editorial: titles, cross-references and numbering. They are written up in `comment/`.

The tests (`python3 -m unittest discover -s tests -v`) cover:

- a fixture with deliberately wrong IDs, which must fail;
- a profile with an injected bad ID, which must fail;
- planted errors that each consistency check must report, so a zero in the report is a measured
  zero;
- that every OT Discussion and rationale appears verbatim in the PDF;
- that a fresh build reproduces the committed files byte for byte.

The PDF tests fail, rather than skip, when the sources are missing.

## Rebuild and validate

```
scripts/fetch_sources.sh                                   # downloads the PDFs, checks SHA-256
python3 scripts/build.py                                    # needs poppler (pdftotext, pdftohtml)
python3 -m unittest discover -s tests -v
OSCAL_CLI=/path/to/oscal-cli scripts/validate.sh            # oscal-cli 3.2.0, Java 21
```

## Limits

- The extractor reads this draft's layout. It will need adjusting for the final publication.
- Table 18's underline (added) and strikethrough (removed) styling is not read, because the PDF
  text layer does not carry it. The same facts come from the E.7 "Add" and "Remove" markers, which
  agree with SP 800-53B. Strikethrough was checked by eye for SC-10 and SI-8(2).
- Rev. 3 contains one printing error that the parser corrects explicitly and reports: PL-8(1) is
  printed as "PL-4 (1)" on PDF page 285.
